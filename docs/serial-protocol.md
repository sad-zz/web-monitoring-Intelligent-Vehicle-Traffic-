# پروتکل سریال دستگاه RATCX1 (اتصال کابلی / ESP01)

> منبع: فریم‌ور `firmware/Main` — فایل‌های `91-7.c`، `UART_Int_Lib.h`، `Variables.h`
> مدل: `RATCX1` — نسخه: `HW:B-06, SW:JA11`

این سند مرجع کامل رابط سریال دستگاه است؛ همان چیزی که در حالت اتصال با کابل دیده/تنظیم می‌شود و پایه حالت بی‌سیم (ماژول ESP01 به‌عنوان پل TCP↔UART) و ترمینال اپ اندروید است.

---

## مشخصات پورت

| پارامتر | مقدار |
|---------|-------|
| پورت | UART1 میکروی اصلی |
| باودریت | **115200** |
| قالب | 8 بیت داده، بدون پریتی، 1 بیت توقف (8N1) |
| پایان فرمان | Enter (کاراکتر CR = 13) |
| Echo | دستگاه هر کاراکتر دریافتی را برمی‌گرداند |
| پایان پاسخ | همیشه یک سطر `OK` |
| Backspace | پشتیبانی می‌شود (کاراکتر 8) |

**پیام بوت:** بعد از هر ریست، دستگاه می‌فرستد:
```
Started, Step:<کد علت ریست RCON>  MMC Error:
```

## جدول کامل فرمان‌ها

هر فرمان یک کد ۴ رقمی است + پارامتر (در صورت نیاز) + Enter.

### فرمان‌های نمایش / وضعیت

| فرمان | عملکرد | پاسخ |
|-------|--------|------|
| `0000` | شناسایی | `sysId,datetime,RATCX1,HW:B-06SW:JA11,READY` |
| `0088` | **نمایش همه تنظیمات** | صفحه وضعیت کامل (جدول پایین) |
| `0007` | فرکانس لوپ‌ها | چهار عدد `235930/caldata` جدا با ویرگول |
| `0046` | شمارش تجمعی کلاس‌ها | ۱۲ سطر: شمارش هر کلاس A تا X در لاین ۱ و ۲ |
| `0197YYMMDDHHmm` | داده بازه ۵ دقیقه‌ای | بسته ۲۶۴ بایتی (ساختار 8821 پایین) |
| بقیه کدها | نامعتبر | تاریخ/ساعت فعلی دستگاه |

### فرمان‌های تنظیم (در EEPROM ذخیره می‌شوند)

| فرمان | قالب | توضیح |
|-------|------|-------|
| `0002` | `0002abcd` | فعال/غیرفعال لوپ‌های ۱ تا ۴ — هر رقم 0/1 (مثال: `00021100`) |
| `0003` | `0003n` | AUTCAL — دستگاه نوع H هست (1) یا نه (0) |
| `0004` | `0004nnn` | فاصله دو لوپ (سانتی‌متر، ۳ رقم) |
| `0005` | `0005nnn` | طول لوپ (سانتی‌متر، ۳ رقم) |
| `0010` | `0010ttbb` | مارجین بالا (۲ رقم) + مارجین پایین (۲ رقم) |
| `0011` | `0011nn` | HMM — حداقل ۱۰ (کمتر وارد شود خودش ۱۰ می‌گذارد) |
| `0012` | `0012yyMMddHHmmss` | تنظیم ساعت RTC |
| `0019` | `0019dddnnndddnnn` | حد سرعت: روز لاین۱، شب لاین۱، روز لاین۲، شب لاین۲ (هر یک ۳ رقم) |
| `0021` | `0021n` | نوع تغذیه: 0=خورشیدی، 1=برق شبانه، 2=پشتیبان، 3=بدون باتری |
| `0022` | `0022nnnnnnnnnnn` | شماره موبایل SMS هشدار (۱۱ رقم) |
| `0023` | `0023<32 کاراکتر>` | نام محل نصب |
| `0032` | `0032n` | APN سیم‌کارت: 0=`mtnirancell`، 1=`mcinet` |
| `0034` | `0034aaa.bbb.ccc.ddd.ppppp` | IP سرور (۴ بخش ۳ رقمی) + پورت (۵ رقم). مثال: `0034141.011.022.033.02022` |
| `0040`…`0045` | `004Xnnnn` | حد طول کلاس‌بندی: 0040=X (نامشخص)، 0041=A (موتور)، 0042=B (سواری)، 0043=C (وانت)، 0044=D (اتوبوس)، 0045=E (کامیون) |

### فرمان‌های عملیاتی

| فرمان | عملکرد |
|-------|--------|
| `0006` | کالیبراسیون هر ۴ لوپ |
| `0008` | روشن/خاموش دیباگ عبور خودرو (کلاس/سرعت لحظه‌ای) |
| `0013` | **ریست میکروکنترلر** |
| `0017` | ری‌استارت مودم GSM (SIM900) |
| `0018` | استعلام کیفیت سیگنال (`AT+CSQ`) — پاسخ `+CSQ: rssi,ber`؛ rssi از 0 تا 31، بالاتر بهتر؛ 99 یعنی نامشخص |
| `0025` | روشن/خاموش دیباگ مودم (نمایش دیالوگ AT روی ترمینال) |

## کدهای خطا (Err)

مقدار `Err` یک **bitmask** است — چند خطا می‌توانند همزمان فعال باشند. همین عدد در بایت‌های [258-261] پیام `8821` هم می‌آید. (جدول مفصل‌تر: [`error-codes.md`](error-codes.md))

| مقدار | نام | معنی | علت / رفع |
|-------|-----|------|-----------|
| 1 | `MMC_ERR` | خطای کارت حافظه | کارت SD خراب/شل — تعویض یا جازدن مجدد |
| 2 | `LP1_ERR` | لوپ ۱ پاسخ نمی‌دهد | قطعی سیم‌پیچ زیر آسفالت یا کانکتور |
| 4 | `LP2_ERR` | لوپ ۲ پاسخ نمی‌دهد | 〃 |
| 8 | `LP3_ERR` | لوپ ۳ پاسخ نمی‌دهد | 〃 |
| 16 | `LP4_ERR` | لوپ ۴ پاسخ نمی‌دهد | 〃 |
| 32 | `VMN_ERR` | ولتاژ شبانه پایین | چک ساعت ۲۲:۳۰ — باتری/شارژر ضعیف |
| 64 | `SOL_ERR` | پنل خورشیدی ضعیف | چک ساعت ۱۱ تا ۱۴ — پنل کثیف/خراب یا سایه |
| 128 | `LBT_ERR` | باتری ضعیف | ولتاژ زیر آستانه (ADC<230) — تعویض باتری |
| 256 | `L1D_ERR` | خطای جهت لاین ۱ | (در این نسخه فریم‌ور ست نمی‌شود) |
| 512 | `L2D_ERR` | خطای جهت لاین ۲ | 〃 |

**مثال:** `Err: 88` → 88 = 64+16+8 → پنل خورشیدی + لوپ ۴ + لوپ ۳ خراب.

منطق ست/ریست شدن خطاها در فریم‌ور:
- **لوپ‌ها**: هر سیکل اندازه‌گیری؛ اگر ورودی Capture پالس نداشته باشد ست، با اولین پاسخ سالم ریست.
- **LBT**: هر ثانیه؛ `vbat < 230` ست، بالاتر ریست. (مقدار نمایشی = `raw×0.388509+7` دهم‌ولت)
- **SOL** (تغذیه سولار): ساعت ۱۱–۱۴ اگر `solar < 200` ست؛ `solar > 250` ریست.
- **VMN** (برق شبانه/پشتیبان): برق شبانه → چک ۲۲:۳۰؛ پشتیبان → هرلحظه `solar < 200`.

## دیباگ عبور خودرو (فرمان `0008`)

بعد از فعال کردن، با هر عبور، دستگاه اطلاعات لحظه‌ای می‌فرستد (کلاس تشخیصی، سرعت، طول/فرکانس لوپ). با ارسال دوباره `0008` خاموش می‌شود. فرمان `0025` همین کار را برای دیالوگ AT مودم GSM انجام می‌دهد — برای عیب‌یابی آنتن‌دهی و اتصال GPRS.

---

## ساختار پاسخ `0197` / پیام `8821`

پاسخ ۲۶۴ بایت است (۲۶۲ + CR LF):

```
[0-7]     شناسه سیستم (۸ رقم)
[8-17]    تاریخ/ساعت بازه YYMMDDHHmm
[18-131]  لاین ۱: ۶ کلاس × ۱۹ کاراکتر
          (شمارش۴ + سرعت‌متوسط۳ + تخلف۴ + فاصله‌مجاز۴ + سرفاصله۴)
[132-134] اشغال (occupancy) لاین ۱
[135-248] لاین ۲: مشابه لاین ۱
[249-251] اشغال لاین ۲
[252-254] ولتاژ باتری
[255-257] ولتاژ سولار
[258-261] کد خطا (error_byte)
```

ترتیب کلاس‌ها در هر لاین: A (موتور)، B (سواری)، C (وانت)، D (اتوبوس)، E (کامیون)، X (نامشخص).

## استفاده بی‌سیم (ESP01)

ماژول ESP-01 با فریم‌ور پل شفاف TCP↔UART (مثل ESP-Link) روی UART1 نصب می‌شود؛ هر بایت شبکه↔سریال عیناً رد می‌شود، پس **تمام فرمان‌های این سند بدون تغییر از راه دور کار می‌کنند**. اپ اندروید همین پروتکل را در تب «ترمینال» حالت WiFi پیاده کرده است. جزئیات سیم‌بندی: [`android/README.md`](../android/README.md).
