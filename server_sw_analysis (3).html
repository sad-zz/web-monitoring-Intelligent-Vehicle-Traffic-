خلاصه: دستگاه‌های شمارنده ترافیکی (TC) از طریق شبکه به پورت ۸۰۹۹ سرور متصل می‌شوند. برنامه داده‌های خام را در SQL Server ذخیره می‌کند، سپس یک تِرد مستقل (RMTO5Thread) این داده‌ها را پردازش و از طریق متد Add5 به سرویس RMTO ارسال می‌کند.

۲. پروتکل ارتباطی دستگاه شمارنده (TCP / ASCII)

⚡ پروتکل: پیام‌ها به‌صورت رشته ASCII با طول ثابت ارسال می‌شوند (حدود ۲۸۷ کاراکتر + CR+LF). سرور پس از دریافت اولیه، مُهر زمانی فعلی را پاسخ می‌دهد ("0012" + yyMMddHHmmss).

۳. ساختار پایگاه داده SQL Server — بانک TCs

جدول mehvar — تعریف محورهای ترافیکی

فیلدنوعتوضیح
mehvar_codevarchar(6) PKکد یکتای محور (= RID ارسالی به RMTO)
cidintشناسه شرکت CID — از همین فیلد خوانده می‌شود
activesmallintاگر 0 باشد داده null ارسال می‌شود
interval_psmallintبازه گزارش‌دهی: 5 = ۵ دقیقه، در غیر این صورت intervalperiod (پیش‌فرض ۱۰)
grab_countsmallintاگر 1 باشد فیلد OO از grab پر می‌شود
lane_nosmallintتعداد خط (۱ یا ۲)
ac, bc, cc, dc, ecfloatضریب تصحیح تعداد برای هر کلاس (پیش‌فرض ۱.۰)

جدول data — رکوردهای ترافیکی (یک ردیف = یک بازه زمانی یک محور)

فیلدنوعارتباط با Add5
idbigint IDENTITY= FID ارسالی (شناسه رکورد)
mehvar_idvarchar(6)= RID (شناسه محور)
intervaldatetime= ET (زمان پایان بازه)
acount…ecountint= C1…C5 (پس از ضرب در ضرایب ac…ec)
avavg…evavgint= S1…S5 (سرعت میانگین هر کلاس)
aspeed…espeedint= SO1…SO5 (تعداد تخلف سرعت)
grabint= OO (تخلف دوربین)
headwayint= ESD (فاصله زمانی)
processedsmallint0=خام / 1=آماده ارسال
RMTO_IDbigint NULLID برگشتی از سرور؛ NULL = هنوز ارسال نشده
RMTO_ERRtextERR برگشتی از سرور
منطق انتخاب رکورد برای ارسال: WHERE RMTO_ID IS NULL AND processed = 1 — رکوردهایی که ضریب تصحیح اعمال شده ولی هنوز پاسخ RMTO دریافت نکرده‌اند. بسته‌های ۵۰۰ تایی (top(500)) ارسال می‌شوند.

۴. منطق RMTO5Thread — تِرد ارسال به RMTO

این تِرد به‌صورت مستقل و موازی اجرا می‌شود. هر ۱۰ ثانیه یکبار SQL را بررسی و رکوردهای آماده را ارسال می‌کند. 
// ۱. آماده‌سازی endpoint — در کد از IP داخلی استفاده می‌شود:
Uri address = new Uri("http://5.160.195.56/Companies/Companies.asmx");
// (در app.config: http://otf.rmto.ir/Companies/Companies.asmx)
EndpointAddress endpointAddress = new EndpointAddress(address);
BasicHttpBinding bind = new BasicHttpBinding();
var csclient = new RMTO.CompaniesSoapClient(bind, endpointAddress);

// ۲. خواندن رکوردهای ارسال‌نشده از SQL:
// SELECT top(500) dt.*, mh.* FROM data dt
//   INNER JOIN mehvar mh ON mh.mehvar_code = dt.mehvar_id
//   WHERE RMTO_ID IS NULL AND processed = 1
//   ORDER BY dt.interval ASC

// ۳. محاسبه فیلدها:
rmtodata.CID  = mh.cid;          // از جدول mehvar
rmtodata.UID  = "ERGSH";         // هاردکد شده
rmtodata.PWD  = "E2&mi(G*p";    // هاردکد شده
rmtodata.FID  = dt.id;           // شناسه رکورد محلی
rmtodata.RID  = dt.mehvar_id;    // کد محور
rmtodata.ET   = dt.interval;     // زمان پایان بازه
rmtodata.ST   = ET - intervalperiod; // ۱۰ دقیقه یا ۵ دقیقه قبل

rmtodata.C1...C5  = acount...ecount;  // تعداد هر کلاس
rmtodata.S1...S5  = avavg...evavg;     // سرعت میانگین کلاس
rmtodata.SO1...SO5 = aspeed...espeed;   // تعداد تخلف سرعت

rmtodata.ASP  = (C1*S1 + C2*S2 + ... + C5*S5) / (C1+...+C5);  // میانگین وزنی
rmtodata.SSO  = SO1 + SO2 + ... + SO5;   // جمع تخلفات
rmtodata.OO   = grab (اگر grab_count==1);
rmtodata.ESD  = headway;

// ۴. ارسال غیرهمزمان:
IAsyncResult ar = csclient.BeginAdd5(
    rmtodata.CID, rmtodata.UID, rmtodata.PWD,
    rmtodata.FID, rmtodata.RID,
    rmtodata.ST, rmtodata.ET,
    rmtodata.C1, rmtodata.C2, rmtodata.C3, rmtodata.C4, rmtodata.C5,
    rmtodata.ASP,
    rmtodata.S1, rmtodata.S2, rmtodata.S3, rmtodata.S4, rmtodata.S5,
    rmtodata.SSO,
    rmtodata.SO1, rmtodata.SO2, rmtodata.SO3, rmtodata.SO4, rmtodata.SO5,
    rmtodata.OO, rmtodata.ESD,
    callback, csclient);

// ۵. Callback — پردازش پاسخ:
RMTO.Re ans = csclient.EndAdd5(ar).Add5Result;
// اگر ans.ID > 0 یا ans.CFL == 100 → ثبت موفق
// UPDATE data SET RMTO_ID=ans.ID, RMTO_FID=ans.FID, RMTO_ERR=ans.ERR ...

منطق null کردن داده (isnull)

شرطعملکرد
C1=C2=C3=C4=C5=0 و vbat=0isnull=1 → تمام فیلدهای ترافیکی = null
mehvar.active = 0isnull=1 → محور غیرفعال، داده null

۵. ساختار درخواست SOAP (متد Add5)

برنامه از SOAP 1.2 (با BasicHttpBinding و messageEncoding="Text") استفاده می‌کند. آدرس: http://otf.rmto.ir/Companies/Companies.asmx — namespace: ITS 
<!-- درخواست SOAP 1.2 -->
<?xml version="1.0" encoding="utf-8"?>
<soap12:Envelope
  xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
  xmlns:xsd="http://www.w3.org/2001/XMLSchema"
  xmlns:soap12="http://www.w3.org/2003/05/soap-envelope">
  <soap12:Body>
    <Add5 xmlns="ITS">
      <CID>80</CID>         <!-- ushort: شناسه شرکت -->
      <UID>ERGSH</UID>       <!-- string: نام کاربری -->
      <PWD>E2&mi(G*p</PWD>   <!-- string: رمز عبور -->
      <FID>12345</FID>       <!-- uint: شناسه رکورد محلی (data.id) -->
      <RID>102030</RID>     <!-- uint: کد محور (mehvar_code) -->
      <ST>2024-01-15T10:00:00</ST> <!-- dateTime: شروع بازه -->
      <ET>2024-01-15T10:10:00</ET> <!-- dateTime: پایان بازه (= data.interval) -->
      <C1>45</C1>           <!-- ushort?: تعداد سواری و وانت -->
      <C2>12</C2>           <!-- ushort?: تعداد مینی‌بوس/کامیونت -->
      <C3>8</C3>            <!-- ushort?: تعداد اتوبوس -->
      <C4>3</C4>            <!-- ushort?: تعداد کامیون -->
      <C5>1</C5>            <!-- ushort?: تعداد تریلر -->
      <ASP>62</ASP>          <!-- ushort?: میانگین سرعت کل (km/h) -->
      <S1>68</S1>           <!-- ushort?: سرعت میانگین C1 -->
      <S2>55</S2>           <!-- ... S3, S4, S5 -->
      <S3>48</S3>
      <S4>52</S4>
      <S5>50</S5>
      <SSO>7</SSO>          <!-- ushort?: جمع کل تخلفات سرعت -->
      <SO1>5</SO1>          <!-- ushort?: تخلف سرعت C1 -->
      <SO2>1</SO2>
      <SO3>1</SO3>
      <SO4>0</SO4>
      <SO5>0</SO5>
      <OO>0</OO>           <!-- ushort?: تخلف دوربین (grab) -->
      <ESD>2400</ESD>       <!-- ushort?: headway (ms) -->
    </Add5>
  </soap12:Body>
</soap12:Envelope>

ساختار پاسخ (Add5Result / Re)

فیلدنوعتوضیح
IDlongشناسه اصلی رکورد در پایگاه داده مرکز. اگر >0 = ثبت موفق
FIDlongهمان FID ارسالی برمی‌گردد (برای تطبیق)
CFLlongتناقض (100 = تکراری اما قابل قبول)
SRVDTdateTimeزمان ثبت روی سرور RMTO
DLYlongتأخیر ارسال (دقیقه)
BILintمقیاس محاسبه کارکرد
ERRstringnull/0 = بدون خطا؛ "Exception" = خطای سرور
نکته: اگر ERR = "Exception" برگردد، برنامه RMTO_ID را به‌روز نمی‌کند (رکورد دوباره ارسال خواهد شد). اگر ID=0 و ERR != "Exception"، مقدار RMTO_ID = 6735 ثبت می‌شود (کد خطای نرم‌افزار).
