# چک‌لیست نصب سرور جدید — TC Manager

## قبل از نصب
- [ ] سرور Ubuntu/Debian با دسترسی root و IP ثابت آماده است
- [ ] اطلاعات حساب RMTO (کد شرکت، کاربر، رمز) در دسترس است
- [ ] سورس کامل پروژه به سرور منتقل شده (مثلاً `/root/tc-src`)

## نصب
- [ ] `bash /root/tc-src/deployment-guide/install.sh` اجرا و بدون خطا تمام شد
- [ ] `/opt/tc-manager/server/.env` ویرایش شد (رمزهای RMTO)
- [ ] `systemctl restart tc-manager` زده شد

## بررسی
- [ ] `systemctl is-active tc-manager` → `active`
- [ ] `ss -tlnp | grep -E ':3000|:2022'` → هر دو پورت گوش می‌دهند
- [ ] داشبورد در مرورگر باز می‌شود: `http://SERVER_IP`
- [ ] ورود با `admin / admin123` موفق است
- [ ] پورت 2022 در فایروال (ufw + پنل دیتاسنتر) باز است

## پیکربندی
- [ ] رمز مدیر از داشبورد عوض شد
- [ ] محورها (با کد RID راهسام) در منوی «محورها» ثبت شدند
- [ ] تنظیمات RMTO در منوی «تنظیمات» بررسی/ذخیره شد
- [ ] (در صورت انتقال) `data.db` سرور قبلی کپی و سرویس ری‌استارت شد

## اتصال دستگاه‌ها
- [ ] IP سرور جدید و پورت 2022 روی دستگاه‌های RATCX1 تنظیم شد
- [ ] در لاگ، handshake دستگاه دیده می‌شود: `journalctl -u tc-manager -f | grep TCP`
- [ ] دستگاه‌ها در منوی «دستگاه‌ها» ظاهر و به محور متصل شدند

## ارسال RMTO
- [ ] بعد از یک بازه (پیش‌فرض ۱۵ دقیقه)، در لاگ `[RMTO]` ارسال موفق دیده می‌شود
- [ ] `sqlite3 /opt/tc-manager/server/data.db "SELECT COUNT(*) FROM rmto_queue WHERE sent=1;"` بزرگ‌تر از صفر است
